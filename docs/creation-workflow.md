# 创作助手流程规则

本文记录本地创作 Agent（Pi）在当前源码中的策略、工作流规划和验证边界。Pi 将固定策略、上下文引用和根据目标集进度推导的步骤建议通过本地协议交给 WeaveClaw；模型调用、业务执行、权限、确认、任务状态和计费由宿主负责。下文中的建议不等同于任务已经提交或完成。

## 回答和决策

- 助手名为小织。用户问“你是谁”时只简短回答“我是小织”。没有业务工具时使用纯文本策略，不声称已执行任务。
- 问及项目、素材或任务时，先读取宿主允许的真实业务数据。不凭聊天历史、模型推测或文件名声称某阶段已经完成；`pipeline/status` 不能单独代表完整的阶段证据。
- 跨轮续接时，`last_episode` 只提供目标线索，不缓存进度或授权写入。用户明确指定其他集数时以当前请求为准；先读取目标集实时进度。相同执行的断点重放与用户发起的新轮次由宿主区分。
- 只陈述实际收到的操作回执和任务状态，区分已提交、执行中、已完成、待采纳和状态待核对。费用以宿主回执为准。
- 展示草图、首帧和其他媒体时使用宿主提供的对应能力，不猜测或拼接素材地址。文件存在不证明内容有效、质量合格或与当前脚本一致。
- 场景／道具规划要求有效的目标集进度、非空 beat 内容和未观测到脚本任务运行；首页范围还要求读取与写入使用同一项目。宿主提交前再次检查；这不证明内容质量，也不构成跨进程原子快照。

## 单轮边界与执行模式

一轮可以进行有限次业务读取。互不依赖的项目、角色、分集、场景、道具、剧本和状态读取可并行提出；依赖前一次结果的操作应分开。模型必须完整返回，Pi 先验证整批参数，宿主再验证、授权并执行。单轮最多启动一个写任务，提交后按回执收口，不轮询至完成再自动提交下一项。

写任务失败后停止本轮，不继续后续工具调用或自动重试。仅当宿主明确表示尚未发起写入，才可在相同目标和版本下对本地参数检查错误修正一次。导入覆盖、版本采纳、任务取消等确认及业务冲突由宿主处理。Pi 只能使用宿主提供的受控工具。

对于整集制作等跨阶段任务，策略要求先说明拆解并询问是否查看进度，再读取状态并提出下一步。默认询问执行模式：

- **逐步确认**：每步前说明并等待用户确认，启动后收口。
- **自动推进**：按最新进度选择下一步；单轮一写的边界仍然适用。跨轮自动调度由宿主负责。

多集范围按集数顺序规划。当前集完成须由新读取的事实确认，下一集也须重新读取；失败或执行中不能凭写回执推进。批次范围最多 20 集。

音频相关字段（`audio_type`、`speaker`、对白文本）的策略顺序为：先更新 beat，再重做该 beat 音频，最后合成；每轮一个写任务。该顺序是策略要求，不能将它理解为本地工作流已维护跨轮顺序状态。

## 流水线

`workflow.mjs` 的 14 个工具检查点如下。完成后展示内容是对话策略要求，具体取决于宿主提供的工具和回执。

| 顺序 | 工具 | 预期产物 |
|------|------|----------|
| 1 | `weaveclaw_start_ingest` | 摄入状态 |
| 2 | `weaveclaw_build_characters` | 角色列表 |
| 3 | `weaveclaw_plan_episodes` | 分集列表 |
| 4 | `weaveclaw_plan_identities` | 身份列表 |
| 5 | `weaveclaw_generate_script` | beat 摘要 |
| 6 | `weaveclaw_assign_sketch_colors` | 草图配色 |
| 7 | `weaveclaw_generate_sketches` | 草图 |
| 8 | `weaveclaw_detect_sketch_identities` | beat 身份汇总 |
| 9 | `weaveclaw_optimize_video_global` | 视频提示词就绪情况 |
| 10 | `weaveclaw_render_first_frames` | 首帧 |
| 11 | `weaveclaw_generate_audio` | 音频 |
| 12 | `weaveclaw_start_single_video` | 视频片段 |
| 13 | `weaveclaw_compose_episode` | 成片 |
| 14 | `weaveclaw_get_final_video` | 成片展示 |

场景／道具规划、配置推荐和首帧质量验证是辅助工具，不增加上述完成步骤。进度只计算已验证的连续完成前缀；草图配色没有独立完成事实，因此草图就绪同时作为配色和生成完成的依据。

## 工作流条件与检查点

以下是 `plan()` 暴露流水线工具的主要条件，均以有效目标集进度为前提；对应阶段有活动任务时不会暴露该阶段工具。`allows()` 还对目标、场景／道具、推荐以及视频、合成和交付等执行额外检查。宿主必须独立验证权限和业务前置条件。

| 工具或步骤 | `plan()` 的主要条件 |
|------------|----------------------|
| 摄入 | `source.uploads > 0` |
| 角色提取 | `source.imported` |
| 分集规划 | 已导入、有角色，且尚无分集或目标集存在 |
| 身份规划 | 目标集存在且有角色 |
| 脚本生成 | 目标集存在且身份已规划 |
| 草图配色 / 生成 | 目标集存在且有 beat；生成还要求所有 beat 有内容 |
| 身份检测 | 有 beat，草图无缺失且无过期 |
| 视频优化 | 草图就绪且所有 beat 已完成身份检测 |
| 首帧生成 | 身份检测完成，且所有 beat 的视频提示词已就绪 |
| 音频生成 | 所有首帧存在，且质量未明确失败或用户已接受失败结果 |
| 逐 beat 视频 | 首帧及质量条件满足，所有 beat 的音频为当前或已确认的未知素材 |
| 合成 | 视频的前置条件满足，且所有 beat 的视频为当前或已确认的未知素材 |
| 成片展示 | 质量和音视频新鲜度条件满足，成片为当前或已确认的未知素材 |

- **配置推荐**：摄入已完成、项目明确未配置且摄入任务未运行时出现 `config_recommendation`。先读取同一目标的原文及版本，再提交匹配来源摘要和版本的建议；该检查点不阻断现有流水线工具。
- **草图过期**：`sketches_stale > 0` 时建议检查或重做草图，以避免旧批次外观不一致；此检查点不额外改变工具门槛，身份检测仍要求草图无过期。
- **首帧审查**：首帧和质量条件满足、音频新鲜度已知、没有当前音频且音频尚未全部就绪时，规划可返回 `review_first_frames`。这是可跳过的检查点，音频工具仍可用；部分音频已就绪但尚未全部就绪时建议 `audio_required`。
- **首帧质量**：批次设置 `quality_required` 且首帧存在但质量未知时，建议 `weaveclaw_verify_first_frames`。质量明确失败且用户尚未接受时，`retry_count === 0` 建议重渲；次数非零或未知时暂停并返回 `quality_failed`。重试计数由宿主维护，重复规划不会消耗次数。
- **素材新鲜度**：音频或视频新鲜度缺失、存在未确认的未知素材时提示核对；过期素材产生相应检查点。未知素材由用户确认使用后仍是未知，不能声称已验证为当前。成片同样区分 `missing`、`current`、`stale` 和 `unknown`。

进度中的可选字段缺失时不会一律当作 0：视频提示词、音频／视频数量、成片状态和新鲜度等缺失时保持未知；`audio_ready` 缺失时回退到 `audio_present`，确认数量缺失时为 0。静音 beat 可由宿主计入音频就绪，但不代表存在音频文件。字段类型、数量越界或新鲜度分组不完整时，整份目标集进度无效，不能用其解锁流水线。
